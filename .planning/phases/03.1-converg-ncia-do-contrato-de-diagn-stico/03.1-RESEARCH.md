## Summary

The live backend currently exposes `DiagnosticStatus` as a Java enum with `AVAILABLE`, `DEGRADED`, and `UNAVAILABLE` [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticStatus.java:4-8]. The published OpenAPI schema and generated Angular model already use exactly `UP`, `DEGRADED`, and `DOWN` [VERIFIED: backend/openapi/betufu.yaml:3869-3874] [VERIFIED: frontend/src/app/api/generated/model/diagnostic-status.ts:12-17]. The phase is therefore an internal vocabulary convergence: update enum references and local diagnostic test prose while leaving the public schema, generated client, HTTP path, profiles, authorization, probes, and aggregation thresholds unchanged.

`DiagnosticService` owns ordering, aggregate-state thresholds, and summary text; `PlatformDependencyProbes` creates the six component statuses; `DiagnosticController` exposes the response only under `dev | homolog`; and `DiagnosticControllerIT` proves authentication, profile absence in production, mapping presence in development, and response projection [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticService.java:35-136] [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/PlatformDependencyProbes.java:53-237] [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticController.java:30-51] [VERIFIED: backend/src/test/java/br/com/betufu/platform/diagnostic/DiagnosticControllerIT.java:188-347].

**Primary recommendation:** perform a strict identifier rename inside the diagnostic package/tests, add a Jackson-focused unit test for exact wire values and rejection of legacy values, then reuse the existing HTTP IT after a clean backend rebuild.

### Pattern 1: Strict enum contract

**What:** Define only `UP`, `DEGRADED`, and `DOWN` in the Java enum, relying on the existing Jackson/Spring MVC default enum name mapping for JSON. Assert `values()` and exact serialized strings in a dedicated unit test [VERIFIED: backend/openapi/betufu.yaml:3869-3874; backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticStatus.java:4-8].

**When to use:** Whenever a public schema already fixes a closed string vocabulary and legacy values must fail rather than be translated [VERIFIED: .planning/phases/03.1-converg-ncia-do-contrato-de-diagn-stico/03.1-CONTEXT.md:15-20].

### Pattern 2: Preserve aggregate semantics during rename

**What:** Rename enum references and local wording without changing comparisons, loop order, component count, deadlines, or probe behavior. Existing unit/IT scenarios remain the behavioral oracle [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticService.java:35-136; backend/src/test/java/br/com/betufu/platform/diagnostic/DiagnosticServiceTest.java:49-214].

### Anti-Patterns to Avoid

- **Global search-and-replace:** It would touch unrelated values such as `END_SESSION_UNAVAILABLE`, HTTP `SERVICE_UNAVAILABLE`, and non-diagnostic domains; D-01/D-03 limit edits to the diagnostic allowlist [VERIFIED: backend/openapi/betufu.yaml:3810-3815; rg triage in live worktree].
- **Compatibility aliases or `@JsonValue`:** They would accept old strings or create dual vocabularies, contradicting D-08/D-11 [VERIFIED: .planning/phases/03.1-converg-ncia-do-contrato-de-diagn-stico/03.1-CONTEXT.md:22-25].
- **Changing probe thresholds while renaming:** This would alter authorization/availability semantics, not merely identifiers [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticService.java:86-118].

## Common Pitfalls

### Pitfall 1: Updating only the enum declaration

**What goes wrong:** Java compilation fails at references in probes/services/tests, or tests still assert old names.
**Why it happens:** Enum constants are referenced throughout the diagnostic package and direct tests [VERIFIED: RepoWise callers and live `rg` results].
**How to avoid:** Rename all allowlisted `DiagnosticStatus.AVAILABLE`/`UNAVAILABLE` references and local test prose; then run focused unit and IT commands.
**Warning signs:** Any old enum identifier remains under `backend/src/{main,test}/.../diagnostic`, or frontend JSON assertions show a legacy value.

### Pitfall 2: Accidentally changing severity semantics

**What goes wrong:** Redis degradation, PostgreSQL/Keycloak failure, or two unavailable components produce a different overall state.
**Why it happens:** Mechanical edits to comparisons or summary branches can alter the reducer [VERIFIED: backend/src/main/java/br/com/betufu/platform/diagnostic/DiagnosticService.java:86-136].
**How to avoid:** Keep branch structure and thresholds byte-equivalent apart from identifiers; retain existing `DiagnosticServiceTest` and `DiagnosticDegradationIT` scenarios.

### Pitfall 3: Accepting legacy JSON values

**What goes wrong:** Compatibility code silently accepts `AVAILABLE`/`UNAVAILABLE`, leaving the public contract ambiguous.
**Why it happens:** Jackson can be customized to accept aliases, but D-08/D-09 explicitly forbid aliases [ASSUMED for Jackson default behavior; locked decision is verified in CONTEXT.md].
**How to avoid:** Dedicated test must assert deserialization of both legacy strings throws, while exact new strings round-trip.

### Pitfall 4: Trusting stale artifacts

**What goes wrong:** A previous JAR/container still emits old values, masking source changes.
**Why it happens:** Build output may outlive source edits; phase history specifically records stale classpath hazards [VERIFIED: .planning/STATE.md:255-267].
**How to avoid:** Run `clean` before the phase's backend verification and validate the live endpoint response.
