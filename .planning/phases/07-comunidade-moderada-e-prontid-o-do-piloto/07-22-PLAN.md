## Review Reconciliation Proposal

Contrato administrativo e consulta de participante sao operacoes distintas.
Adicionar endpoints GET /api/v1/chat/events/{eventId}/availability,
GET /api/v1/chat/global/availability e GET
/api/v1/predictions/markets/{marketId}/availability, implementados em 21.
Propor operationIds getEventChatAvailability, getGlobalChatAvailability e
getPredictionMarketAvailability na tag EmergencyPauses para reusar o service
oficial desta fatia; tag de cliente nao muda propriedade modular dos controllers.
Public event/market security anonima e global security de sessao devem ser
explicitos; nenhuma rota permite consultar a disponibilidade de outra conta.

Producer reconciliation under continuous owner execution/self-healing authority:
EmergencyPauseAvailability is the closed public DTO (state, applicable domain
flag and nullable opaque revision). EmergencyPauseState is the separate private
administrative receipt (factId, kind, targetId, action, reason, resumedPauseId,
recordedAt). Java emits no view/status discriminator. Availability never exposes
administrative fields. The unchanged index.ts path is replaced by the new
availability model, preserving the 15-path primary limit. Prediction availability
uses the implemented /api/v1/me/predictions/markets/{marketId}/availability route;
RESUME uses POST at the operations root with action and resumedPauseId.
PLAN reconciliation is supplemental bookkeeping, not a runtime dependency change.

Gerador deve inventariar TODAS as variantes e outputs reais: reusar o modelo
declarado somente se o engine aprovado realmente permitir. Se variantes
gerarem arquivos alem dos 15, BLOCKED: propor subdivisao/allowlist antes de
publicacao, nunca omitir outputs, editar generated ou achatar privacidade para
caber no limite. Tests do gerador verificam segregacao de security, schemas
e nomes; tests runtime/privacy sao de 21 e E2E de 23.
