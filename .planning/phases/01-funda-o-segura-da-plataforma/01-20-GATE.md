- `generate:api` e `generate:api:check` não podem permitir download automático nem invocar um version manager do wrapper;
- o runner chama somente o JAR já adquirido e verificado, por caminho aprovado;
- geração/check normais falham se o JAR estiver ausente, tiver tamanho divergente ou SHA-256 divergente;
- o hash do JAR é conferido antes e depois de cada geração/check.

## Sequência bloqueante do Gate

1. **Checkpoint A — identidade/exceção/localização.** Apresentar wrapper, JAR, matriz, spike e caminho de cache proposto. Sem aceite, não editar arquivos da Task 1.
2. **Task 1 autorizada.** Criar contrato, configuração e pipeline/testes estáticos; nenhuma rede, npm ou Java.
3. **Checkpoint B — Task 1.** Revisar a entrega estática e autorizar especificamente a Task 2; essa aprovação não autoriza instalação, aquisição ou Java.
4. **Task 2 autorizada.** Alterar somente `package.json`/lock e executar a resolução abaixo com scripts desabilitados.
5. **Checkpoint C — grafo e risco.** Apresentar diff semântico, novo SHA-256, origens, integridades, `npm ls`, stdout JSON completo do audit, exit code separado, allowlist observada e riscos. Achados `critical`/`high` não podem ser aceitos silenciosamente: qualquer aceite, se sequer permitido, exige decisão humana futura registrada e mantém o Gate global `pending`.
6. **Checkpoint D — autorização da instalação.** Somente se os campos anteriores permitirem prosseguir, pedir autorização material exclusiva para `npm ci --ignore-scripts`, hashes do lock antes/depois e `npm audit signatures`. A aprovação do Checkpoint C não autoriza este bloco.
7. **Bloco material npm, sem JAR.** Executar apenas instalação e assinaturas, provar lockfile imutável e parar no Checkpoint E. A autorização deste bloco não autoriza aquisição nem Java.
8. **Checkpoint F — autorização da aquisição.** Pedir nova autorização material exclusiva para obter o JAR aprovado.
9. **Bloco material JAR, sem Java.** Adquirir como arquivo parcial, validar tamanho/hash, renomear sem sobrescrever destino e validar novamente; parar no Checkpoint G. Aprovações anteriores não autorizam este bloco nem a execução do binário.
10. **Checkpoint H — primeira execução Java/Task 3.** Somente após revisar as duas provas, pedir autorização específica para a Task 3 e para a primeira invocação do JAR.
11. **Task 3 autorizada.** Gerar, integrar e testar. Depois, executar a prova agregada somente com autorização própria no Checkpoint I.
12. **Git fora das tasks.** Stage, commit e push têm checkpoints e aprovações separados.

## Comandos auditáveis — PowerShell 5.1

Cada chamada captura `$LASTEXITCODE` imediatamente. Não usar `&&` nem `npm --prefix`.

### Resolução e auditoria do lockfile — somente após autorização da Task 2

```powershell
$npmExitCode = 1
Push-Location -LiteralPath frontend
try {
  npm.cmd install --package-lock-only --ignore-scripts
  $npmExitCode = $LASTEXITCODE
}
finally {
  Pop-Location
}
if ($npmExitCode -ne 0) { exit $npmExitCode }

$lockHash = (Get-FileHash -Algorithm SHA256 -LiteralPath 'frontend/package-lock.json').Hash
Write-Output "CANDIDATE_LOCK_SHA256=$lockHash"
```

Depois da auditoria estática de todas as entradas do lockfile — origem exclusivamente `https://registry.npmjs.org/`, integridade SHA-512 e inventário `hasInstallScript` — executar:

```powershell
$npmLsExitCode = 1
$npmAuditExitCode = $null
$auditStdoutLines = @()
Push-Location -LiteralPath frontend
try {
  npm.cmd ls --all --package-lock-only
  $npmLsExitCode = $LASTEXITCODE
  if ($npmLsExitCode -eq 0) {
    $auditStdoutLines = @(npm.cmd audit --audit-level=high --json)
    $npmAuditExitCode = $LASTEXITCODE
  }
}
finally {
  Pop-Location
}
if ($npmLsExitCode -ne 0) { exit $npmLsExitCode }

$auditJson = $auditStdoutLines -join [Environment]::NewLine
if ([string]::IsNullOrWhiteSpace($auditJson)) { throw 'npm audit não produziu stdout JSON válido.' }
try {
  $auditReport = $auditJson | ConvertFrom-Json -ErrorAction Stop
}
catch {
  throw "stdout de npm audit não é JSON parseável: $($_.Exception.Message)"
}
if ($null -eq $auditReport.metadata) { throw 'JSON de npm audit não contém metadata.' }

Write-Output "NPM_AUDIT_EXIT_CODE=$npmAuditExitCode"
Write-Output 'NPM_AUDIT_JSON_BEGIN'
Write-Output $auditJson
Write-Output 'NPM_AUDIT_JSON_END'
```

Falha de `npm ls` encerra antes do audit. Falha técnica que deixe stdout vazio, JSON inválido ou sem `metadata` bloqueia. Se o JSON for válido, o exit code do audit é evidência para deliberação, não motivo para descartar o relatório antes do Checkpoint C. Parar e apresentar JSON completo + código. Não instalar e não “corrigir” o grafo. Achados `critical`/`high` não fecham o Gate: qualquer aceite de risco, se futuramente permitido, precisa ser humano, explícito e registrado, e `status` continua `pending`.

### Instalação e assinaturas — somente após aprovação do Gate para instalação e autorização material separada

```powershell
$lockHashBefore = (Get-FileHash -Algorithm SHA256 -LiteralPath 'frontend/package-lock.json').Hash
$npmCiExitCode = 1
$signatureExitCode = 1
Push-Location -LiteralPath frontend
try {
  npm.cmd ci --ignore-scripts
  $npmCiExitCode = $LASTEXITCODE
  if ($npmCiExitCode -eq 0) {
    npm.cmd audit signatures
    $signatureExitCode = $LASTEXITCODE
  }
}
finally {
  Pop-Location
}
if ($npmCiExitCode -ne 0) { exit $npmCiExitCode }
if ($signatureExitCode -ne 0) { exit $signatureExitCode }
$lockHashAfter = (Get-FileHash -Algorithm SHA256 -LiteralPath 'frontend/package-lock.json').Hash
if ($lockHashAfter -ne $lockHashBefore) { throw 'package-lock.json mudou durante npm ci/audit signatures.' }
```

### Aquisição explícita do JAR — somente após caminho e JAR aprovados e autorização material separada

O executor deve obter `approved_engine_cache_path` do frontmatter já aprovado, resolver o caminho absoluto e provar que ele fica dentro de `frontend/tmp/`. Se o campo estiver nulo, fora do escopo ou atravessar symlink/reparse point, parar. Então:

```powershell
$expectedLength = 31904922
$expectedHash = '4B83CCC6FD43056C8C631CD0195E5100BD0550912502527BAB09AC76152DAB0C'
$jarUrl = 'https://repo1.maven.org/maven2/org/openapitools/openapi-generator-cli/7.24.0/openapi-generator-cli-7.24.0.jar'
$nonce = [Guid]::NewGuid().ToString('N')
$partialPath = "$approvedJarPath.partial.$nonce"

if (Test-Path -LiteralPath $approvedJarPath) { throw 'Destino do JAR já existe; aquisição não sobrescreve.' }
Invoke-WebRequest -UseBasicParsing -Uri $jarUrl -OutFile $partialPath
if ((Get-Item -LiteralPath $partialPath).Length -ne $expectedLength) { throw 'Tamanho do JAR divergente.' }
if ((Get-FileHash -Algorithm SHA256 -LiteralPath $partialPath).Hash -ne $expectedHash) { throw 'SHA-256 do JAR divergente.' }
[System.IO.File]::Move($partialPath, $approvedJarPath)
if ((Get-Item -LiteralPath $approvedJarPath).Length -ne $expectedLength) { throw 'Tamanho pós-rename divergente.' }
if ((Get-FileHash -Algorithm SHA256 -LiteralPath $approvedJarPath).Hash -ne $expectedHash) { throw 'SHA-256 pós-rename divergente.' }
```

`$approvedJarPath` só pode ser definido a partir do caminho exato aprovado no Gate; não há default implícito.
