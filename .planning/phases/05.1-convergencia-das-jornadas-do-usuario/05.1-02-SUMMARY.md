# Plan 05.1-02 Summary

Preserved the originating Angular route through the hosted OIDC login while
keeping redirect authority and one-time state on the server.

## Delivered

- Added `GET /login/start?returnTo=<path>` as the sole contextual-login entry.
  It validates the target before creating a session and then redirects only to
  the fixed `/oauth2/authorization/keycloak` endpoint.
- Added a central fail-closed target policy. It accepts only canonical internal
  paths and rejects external origins, network paths, backslashes, control
  characters, double slashes, dot segments and technical login/logout/API
  routes.
- `SessionLifecycleService` now consumes and removes the contextual target
  before redirecting. It revalidates session state, discards any older saved
  request and preserves the established saved-request and role fallbacks when
  no explicit target exists.
- The public-market ticket derives the login URL from `Router.url`, encodes it
  as a single query parameter and stores neither destination nor OIDC material
  in browser storage.

## Security Properties

- The client-controlled value is validated both before session storage and
  immediately before use.
- The session attribute is removed before the final redirect, so success,
  refresh or a later login cannot replay it.
- A contextual target has explicit precedence over a saved request; after use,
  neither value survives to override the next role-based fallback.
- Invalid or tampered session state fails closed and invalidates the session.
- Browser-real OIDC return remains assigned to the integrated Playwright
  certification in Plan 05.1-07; this plan changes no Keycloak realm data.
