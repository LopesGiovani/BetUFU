# Plan 05.1-03 Summary

Made the public Arena shell reflect the same authenticated session already used
by protected account and betting features.

## Delivered

- Added `ArenaSessionSummaryStore`, an Arena-owned Signals facade over the
  existing `SessionStore` and generated credit ledger client.
- Session discovery completes before the balance request starts, so anonymous
  users never trigger a private credit call.
- The shell displays a neutral checking state, contextual login for visitors,
  and the authenticated user's display name, balance, Minha conta and Sair
  actions on desktop and mobile.
- Balance failures degrade to `Saldo indisponível` without hiding account or
  logout actions and without rendering backend error details.
- Logout clears the balance immediately and advances a request generation
  counter so a late HTTP response cannot restore stale credit state.
- The existing contextual-login helper updates the return target after Angular
  navigation, preserving the current Arena route for authentication.

## Security And Accessibility

- No token, credential or balance data is persisted in browser storage.
- Only the authenticated user's existing display name and own balance are
  rendered; authorization remains enforced by the backend.
- Login remains an anchor, logout remains a native button, both responsive
  variants preserve minimum touch targets and visible focus, and dynamic
  session/balance text uses polite live status semantics.
- User-controlled display names are rendered through Angular interpolation;
  the component spec proves markup is escaped rather than interpreted.
