# Plan 05.1-04 Summary

Replaced the profile's static enrollment label with the authoritative active
enrollment state while preserving the existing private HTTP contract.

## Delivered

- Added the consumer-owned `ProfileEnrollmentStatusLookup` boundary in the
  `identity` module. Its contract exposes only `REGISTRADA` or
  `NAO_REGISTRADA`.
- Added `ProfileEnrollmentStatusAdapter` inside `verification.internal`. It
  implements the public identity contract through the existing
  `EnrollmentEligibility` API and never returns an enrollment entity,
  matricula, digest, HMAC version or timestamp.
- `ProfileController` now resolves the status by server-side `identityId` for
  reads and writes. The `DEFAULT_MATRICULA_STATUS` constant was removed.
- The `CurrentProfileResponse` shape and generated Angular client remain
  unchanged; no OpenAPI regeneration was necessary.

## Verification

- Required profile and Modulith focal command passed: 28 tests, zero failures,
  errors or skips.
- Adapter and privacy architecture tests passed: 36 tests, zero failures,
  errors or skips.
- Angular profile component spec passed: 16/16 tests in one file.
- Scoped Spotless check passed for all six Java files changed by the plan.
- `git diff --check` passed and no production file imports another module's
  `*.internal.*` package.
- The first literal PowerShell invocation did not reach Maven because the
  comma in `-Dtest` was parsed as an argument separator. Repeating the same
  property inside single quotes executed the intended test classes and passed.

## Privacy And Architecture

- `identity` owns the minimal contract it consumes; `verification` supplies
  the adapter. This preserves the Spring Modulith dependency direction.
- The profile status is derived only from the authenticated account's
  server-resolved UUID. The client cannot select another identity.
- Unexpected lookup failures are not converted into a false
  `NAO_REGISTRADA`; they continue through the platform's normal safe error
  handling.
- Integration coverage proves an active database row produces `REGISTRADA`
  while the response still omits `matricula` and `hmac` fields.
