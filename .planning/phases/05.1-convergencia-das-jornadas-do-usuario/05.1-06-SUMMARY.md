# Plan 05.1-06 Summary

Added an explicit session gate for protected Angular routes and distinct,
accessible navigation states for authentication required and route not found.

## Delivered

- Added `authenticationGuard`, which loads the BFF session only from the
  initial checking state and fails closed to an internal `UrlTree` when the
  session is anonymous, expired or logged out.
- Protected routes now run authentication before profile completion, so an
  anonymous deep link cannot render a private page or fall into profile
  onboarding before login.
- Added the public `/entrar` state with a safe contextual login URL, a clear
  explanation and a direct return to the Arena.
- Added the final `**` wildcard with a distinct 404 page and an Arena action.
- Both states move focus to their page title after navigation, retain the
  global visible focus treatment and use semantic links with touch-sized
  targets.
- Updated the route-boundary validator to approve only the new lazy routes and
  reject reversed guards, a missing authentication guard or any route after
  the wildcard.

## Verification

- The initial focal run failed because the guard and state components were
  absent, proving the new tests discriminate the old behavior.
- Required guard, page and route specs passed: 4 files and 18/18 tests.
- Angular aggregate passed: 69 files and 424/424 tests.
- Node aggregate passed: 752/752 tests across 9 suites, including 178/178
  route-boundary mutation tests.
- Frontend lint passed.
- Production Angular build passed. Existing component-style budget warnings
  remained in unchanged files; neither new state page exceeded the budget.
- Scoped Prettier, route-boundary validation and `git diff --check` passed.

## Security And Navigation Properties

- The guard uses `SessionStore` and an internal `UrlTree`; it does not store
  tokens, destinations or OIDC state and does not call `window.location`.
- Query parameters and fragments remain inside the encoded `returnTo` value.
  The login page reuses the fail-closed helper from Plan 05.1-02 before linking
  to the server-owned `/login/start` endpoint.
- The login-required route is public and precedes the protected branch. The
  wildcard is the final root route, so neither state is captured by the other.
- Messages expose no role, internal endpoint, identifier or other private
  account data. Spring Security remains the authorization authority.

## Deviations From Plan

- The existing route-boundary validator rejected the two approved lazy routes
  because its textual allowlist represented the previous `APP_ROUTES` shape.
  Under the mechanical allowlist exception in `AGENTS.md`, the validator and
  its mutation suite were updated and included in the technical commit.
- A scoped Prettier invocation initially reformatted both validator files. The
  formatting-only diff was removed before reapplying the focused 75-line
  validator change; no unrelated script formatting entered the commit.
